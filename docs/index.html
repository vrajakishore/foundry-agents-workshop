Your first agent, in code


project = AIProjectClient(
    endpoint=PROJECT_ENDPOINT,
    credential=DefaultAzureCredential(),
)
openai = project.get_openai_client()

agent = project.agents.create_version(
    agent_name="fault-diagnosis",
    definition=PromptAgentDefinition(
        model="gpt-5.4",
        instructions="You diagnose faults on tyre-plant machines.",
        tools=[CodeInterpreterTool()],
    ),
)

response = openai.responses.create(
    input="CP-003 vibration is 2x baseline. Likely cause?",
    extra_body={"agent_reference": {"name": agent.name, "type": "agent_reference"}},
)
print(response.output_text)
1Connect to the project with Microsoft Entra ID. No keys.
2Define the agent: model, instructions, tools. Each call creates a new version.
3Call it through the Responses API by name.
✓The same agent shows up in the portal, the playground, traces and evaluations.

📎 Quickstart: create a prompt agent · package azure-ai-projects 2.x

This is the pattern used throughout the lab. DefaultAzureCredential means no API keys anywhere. The lab's agents.py uses the same pattern with a check_thresholds function tool.

Acting safely: a tool call that waits for approval


tool = MCPTool(
    server_label="cmms",
    server_url="https://<your-cmms-mcp-endpoint>/mcp",
    require_approval="always",
    project_connection_id="cmms-connection",
)
# ...create the agent with tools=[tool], then call it...

approvals = []
for item in response.output:
    if item.type == "mcp_approval_request" and item.id:
        ok = supervisor_approves(item.name, item.arguments)
        approvals.append(McpApprovalResponse(
            type="mcp_approval_response",
            approve=ok,
            approval_request_id=item.id,
        ))

response = openai.responses.create(
    input=approvals,
    previous_response_id=response.id,
    extra_body={"agent_reference": {"name": agent.name, "type": "agent_reference"}},
)
1The agent decides a work order is needed and proposes the tool call.
2Execution pauses: tool name and arguments go to a person, in your UI or a Teams card.
3Approved: the tool runs. Rejected: the agent explains and stops.
⏱Every request and decision is in the trace.

📎 Connect an agent to an MCP server · supervisor_approves is your own approval UX

This is the code behind a human approval before a tool runs. The portal workflow designer offers the same approval step without code. Nothing is written to the maintenance system until a supervisor approves.
